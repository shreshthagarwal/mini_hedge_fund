# System Audit — 2026-10-21

In-depth review of the backtesting engine, the five strategies, the live paper
engine and the deployment setup. Written before the first server deployment so
future work starts from a known list of problems.

**Bottom line:** none of the backtest numbers in the README can be trusted, and
paper-trading P&L will not be comparable to backtests until the items in
sections 1–3 are fixed. The infrastructure (data fetch, live feed, dashboard,
per-strategy configs) is a good base; the problems are in data quality, cost
modelling, backtest/live divergence and several strategy-level bugs.

## 1. Data — CRITICAL

### 1.1 Futures CSV mixes two contracts
`data/nifty_futures_5min.csv` has bars from the near-month and next-month
contracts mixed together (30–46 % of bars in most months come from the next
month). Root cause: in `scripts/build_history_upstox.py`,
`pd.concat(all_new).sort_index()` (unstable sort) is followed by
`duplicated(keep="first")`, so which contract survives for each timestamp is
arbitrary. Effects:
- Price jumps by about 100 points from bar to bar wherever the contract flips.
  ATR, ADX, VWAP, RSI and every SL/target distance computed from them are wrong.
- S5's backtest profit is almost entirely this artifact.
- S4 (RL scalper, tight ATR stops, 1,968 trades) is probably also trading
  these fake jumps.

**Fix:** refetch with an expiry-aware merge: for each timestamp, keep the
contract that was front month on that date (roll about 2 days before expiry, see
`utils.roll_date`). Validation: the 5-min return correlation between futures and
the spot proxy should be > 0.9, and there should be almost no same-session bars
where the basis jumps by more than 40 points.

### 1.2 CSV is stale (ends 2026-09-11)
The live engine warms up from `df.tail(300)` of this CSV and then appends today's
bars. With a gap of six weeks or more, the first live bar's true range covers the
whole gap. That inflates ATR and ADX for dozens of bars, so the first trades of
the day get very wide stops. **Fix:** refresh the CSV before each session, or
better, have warmup fetch the last ~5 sessions from the Upstox historical API
instead of reading the CSV.

### 1.3 Smaller data issues
- The CSV contains a `15:30` bar, which is outside the session.
- The spot proxy (yfinance `^NSEI`) has `volume = 0`, so VWAP is NaN on proxy
  data and S2 can never trade on it.
- yfinance 5-min history only goes back about 60 days. The "2015 to present"
  proxy can't be 5-min data for most of that range.

## 2. Backtest engine (`src/engine.py`, `src/risk_management.py`) — CRITICAL

### 2.1 Costs are understated by about 13×
The model charges `COMMISSION_PER_LOT * 2` = ₹80 per round trip. A realistic
round trip for 1 NIFTY futures lot (about ₹17–19 L notional) includes brokerage
(~₹40), STT on the sell side, exchange transaction charges, stamp duty, GST and
the SEBI fee. That comes to **about ₹1,050–1,100 per round trip** at the STT rate
of 0.05 % (Budget 2026; verify the current rate), or about ₹650 at the old 0.02 %.
That's 9–15 NIFTY points per trade before slippage.

Saved `strategies/*/outputs/trades.csv` re-costed with ~₹1,085/trade plus 0.5 pt
slippage per side:

| Strategy | Trades | Avg pts/trade | Net (as saved) | Net (realistic costs) |
|---|---|---|---|---|
| S1 ORB | 51 | 15.7 | +₹56,100 | **≈ ₹0** |
| S2 VWAP | 126 | 2.5 | +₹13,264 | **−₹1.22 L** |
| S3 Candle | 929 | 2.0 | +₹64,992 | **−₹9.4 L** |
| S4 RL | 1,968 | 7.5 | +₹9.54 L | **−₹11.9 L** |
| S5 Basis | 296 | 22.2 | +₹4.69 L | +₹1.47 L (but see 1.1, artifact) |

These signs hold at the old 0.02 % STT rate too. **Any strategy that averages under
about 15 points per trade has no edge after costs.** All of this is also on the
contaminated data from 1.1.

### 2.2 Lot size is probably out of date
Every config uses `LOT_SIZE = 75`. NSE changed the NIFTY lot size to 65 for
contracts from Jan 2026. Verify this and update all five configs, plus
`environment.py` for S4.

### 2.3 Intrabar ordering favours wins (risk-managed path)
`PositionRiskManager.check()` checks **T2 before SL**. When a bar touches both,
the trade is booked as a win. The README claims "pessimistic: SL wins if both
touched". That's only true of the fallback path, which is no longer used now that
`use_risk_mgmt=True`. **Fix:** check the SL first.

### 2.4 Stops never gap
SL exits always fill at the SL price, even when the bar opened beyond it. They
should fill at `min(open, sl)` for longs and `max(open, sl)` for shorts. This
applies to both engine paths and to `TradingEnv`.

### 2.5 The "dual target" turns every target into 1R
With `max_lots = 1`, a T1 hit does `lots_exit = max(1, round(1 * 0.5)) = 1`, which
exits the **whole** position at T1 (1.0R, or 0.8R for S2/S4). T2, trailing and the
strategy's own `rr` are effectively dead code. The backtest really tests
"target = 1R", not what the signals describe.

### 2.6 Strategies stop seeing bars while in a position
`engine.run` only calls `strategy.on_bar()` when flat with no pending signal. S3
and S4 keep their own `_bar_buffer` inside `on_bar`, so their history has gaps
(missing bars, non-contiguous patterns, wrong RL states). The live engine
**does** call `on_bar` while in a position, so backtest and live see different data.

### 2.7 "Walk-forward" isn't walk-forward
`walk_forward()` just splits the data into one-month chunks and resets each
strategy. Nothing is trained on the previous six months, the parameters (e.g. S1
`ORB_SKIP_SLOTS`, the dead zone) were tuned on the full dataset, and S3 auto-loads a
model trained on all the data (see 4.3). The concatenated equity curve also resets
to the starting capital every fold, so drawdown and Sharpe from `compute_metrics`
are wrong.

### 2.8 Minor
- The time-stop exits at the bar's open after already using that bar's high/low
  to rule out the SL. That's a small look-ahead.
- The equity curve is realized-only (no mark-to-market), which understates drawdown.
- Slippage is 1 tick (0.05). Market orders at bar open realistically cost 0.5–1 pt.

## 3. Live paper engine (`src/multi_engine.py`, `src/live_feed.py`) — HIGH

### 3.1 Three different exit models
| | Backtest | Live paper | S4 training env |
|---|---|---|---|
| Exits | `RISK_CONFIGS` (T1 at 0.8–1R, BE at 0.4–0.7R, trailing at 0.3–0.5R, time stop 10–30 bars) | `StrategyState.check_exits` (T1 = midpoint, BE only after T1, trail by full `sl_dist`, `MAX_HOLD_BARS`) | own SL/target, `MAX_HOLD_BARS = 8`, agent exit |
| Entry | next bar open + 1 tick | signal bar close ± 1 tick | signal bar close ± 1 tick |

Paper results therefore **cannot validate the backtests**. **Fix:** make live
use `PositionRiskManager` from `risk_management.py`, the same code the backtest
uses.

### 3.2 Configs were "converted to 1-min", but the system runs on 5-min bars
Comments throughout say "N × 1-min bars", but `BAR_MIN = 5` and the CSVs are 5-min:
- S1 `OR_BARS = 30` makes the opening range **09:15–11:45 (2.5 h)** instead of 30 min.
  Combined with the dead zone, skip slots and the 13:30 cutoff, entries can only
  happen between 11:45 and 13:30. That's why S1 has only 51 trades in 18 months.
- `MAX_HOLD_BARS` (8–10, meant as "minutes") becomes 40–50 minutes live.
- S2 `VWAP_SLOPE_BARS = 50` is 250 min; S3 `SR_LOOKBACK_BARS = 300` is 4 days;
  `CNN_*` counts are 5× too large; S5 `BASIS_ZSCORE_WINDOW = 7500` is 100 days.

### 3.3 S5 z-score is a different statistic live
The live `bar_buffer` is capped at 400–500 bars, so the live z-score uses at most
400 bars (`min_periods = 20`) while the backtest uses 7,500. Same problem for
`basis_std`.

### 3.4 Intelligence layer blocks the feed thread
`_on_candle` holds `self._lock` and calls `IntelligenceEngine.update()`, which makes
synchronous network calls: about 8 yfinance tickers, an NSE option-chain scrape every
bar, and Upstox OI. During that time ticks aren't processed and `/api/state` (which
needs the same lock) hangs. **nseindia.com usually blocks AWS IPs**, so expect
the sentiment fetch to time out (up to 15 s) on every bar on Lightsail. The regime
gate was also never backtested; it's untested live-only logic. **Fix:** run the
intelligence refresh in its own thread with a cache, or turn the gate off for the
first paper run.

### 3.5 Paper trades aren't saved
`StrategyState.trades` only lives in memory. A restart (needed daily for the token)
loses the whole record. **Fix:** append each closed trade to
`outputs/paper_trades_<date>.csv`.

### 3.6 Session state assumes a daily restart
`new_day` is always False. `session_pnl`, the session VWAP/ORB and the dashboard
OHLC never reset. `context["session_bar"]` is `len(bar_buffer)` (300+), not the
bar index within the session. There's also no daily-loss circuit breaker live,
even though the backtest has one.

### 3.7 Feed robustness
- There's no staleness watchdog. If the WebSocket silently stalls, candles stop
  closing, exits stop being checked and square-off never happens.
- `_prime_strategies()` runs **after** `feed.start()` without the lock, so a live
  candle can race with priming on the same strategy objects.
- The first live candle is partial, because the feed joins mid-bucket.
- Ticks outside session hours aren't filtered.

### 3.8 systemd shutdown
`main.py paper` only cleans up on `KeyboardInterrupt`. A systemd unit must use
`KillSignal=SIGINT`, or the session summary and any future CSV flush will be skipped.

## 4. Strategies

### S1 — ORB + ADX
- OR window is 2.5 h (see 3.2). That's the biggest single problem.
- `ORB_SKIP_SLOTS` and the dead zone were picked from backtest results, which is
  overfitting to time slots.
- About 15.7 pts/trade gross, which is about break-even after realistic costs. Fix the
  OR window first, then re-evaluate.
- Indicators are causal; there's no look-ahead in the signal logic.

### S2 — VWAP reversion + RF
- **RF labelling bug:** `outcome = 1 if reason == "target" else 0`, but exit
  reasons are now `"target-T1"`, `"target-T2"`, `"stop-loss…"` etc. (and `"exit"`
  live). Every label is 0. After 100 samples the RF trains on one class,
  `predict_proba` returns 0.5 < 0.55, and **S2 blocks every trade from then on**.
- `prev_day_close` is actually today's first close (groupby-first then shift(1)),
  so the feature is mislabelled.
- `ATR_SL_MULT = 0.5` gives about 8–10 pt stops, which is less than the round-trip
  cost. The strategy can't make money as configured.
- 2.5 pts/trade gross, so it's negative after costs.

### S3 — Candlestick + "CNN" S/R
- The "CNN" is an sklearn `MLPClassifier` on flattened images (fine, but name it
  honestly).
- **Model leakage:** `SRDetector.__init__` auto-loads `sr_cnn.pkl`, which was
  trained on the whole dataset, and `reset()` reloads it. Backtests (including
  "walk-forward") use a model that has seen the future.
- The S/R-adjusted SL `min(ATR, |close − sr| + 0.1·ATR)` can shrink to 1–2 points,
  which is far below costs. It needs a floor (e.g. ≥ 15 pts or ≥ 1 ATR).
- 929 trades at 2 pts/trade gross is very negative after costs.

### S4 — RL scalper (PPO)
- The agent's EXIT action is ignored at execution (`pass`), but it was trained in
  an environment where EXIT works. The policy is used out of context.
- Backtest `reset()` throws away the loaded model, so the "Load existing PPO
  model?" prompt does nothing.
- Live training kicks in after 1,500 `on_bar` calls, runs inside the feed lock on a
  2-vCPU box, and overwrites `ppo_policy.pkl` with a model trained on
  contaminated CSV bars. With a daily restart it won't normally reach 1,500,
  but it should be disabled live anyway.
- The model in `ppo_policy.pkl` was trained on the contaminated data.
- 7.5 pts/trade gross is clearly negative after costs.

### S5 — "Basis arbitrage"
- **It isn't arbitrage.** It trades only the futures leg, with no spot or
  ETF hedge, so P&L is directional NIFTY exposure triggered by a basis signal.
- SL/target are set in futures points from `basis_std` (a few points), so they're
  noise-sized. Exits never look at the z-score again; `ZSCORE_TARGET`/`ZSCORE_STOP`
  only set distances at entry.
- The backtest profit comes from contract interleaving (1.1). Earlier analysis on
  cleaned data showed about ₹1.5k total.
- `nse_expiry()` doesn't adjust for holidays (when the last Tuesday is a holiday,
  expiry moves earlier).

## 5. What's solid
- Next-bar-open fills in the backtest, and pending signals are cancelled across
  sessions.
- Per-strategy configs and a common `StrategyProtocol`.
- Indicators are causal (EWM/rolling, per-day VWAP).
- `.env`-based secrets, the dashboard bound to localhost, and manual trades gated
  behind `ALLOW_MANUAL_TRADES`.
- Live feed parsing for V3 full/ltpc, and the 1-min → 5-min warmup aggregation
  that drops the still-forming bucket.

---

## 6. Recommended fix order

**Before / during the first paper week** (so paper data is usable):
1. Persist paper trades to CSV (3.5).
2. Move the intelligence refresh off the lock, or disable the gate (3.4).
3. Use realistic costs and the current lot size in all configs (2.1, 2.2).
4. Refresh the futures CSV with the expiry-aware merge (1.1, 1.2).
5. Use `KillSignal=SIGINT` in the systemd unit (3.8).

**Then, before trusting any number:**
6. Use one exit model: live uses `PositionRiskManager` (3.1); check SL before T2
   (2.3); fill stops with gaps (2.4); decide whether you want real partials
   (2 lots) or a single target (2.5).
7. Fix the 1-min/5-min parameter confusion in every config (3.2).
8. Always call `on_bar` in the backtest (pass `in_position`) so it matches live (2.6).
9. S2 label fix, S3 model leakage + SL floor, S4 disable live training + honour EXIT,
   S5 rethink as a hedged pair or drop it.
10. Real walk-forward: train/tune on the window, test out of sample, and keep
    equity continuous (2.7).
11. Re-run every backtest. Only strategies with average gross pts/trade well above
    about 15 (the cost line) are worth paper-trading seriously.
